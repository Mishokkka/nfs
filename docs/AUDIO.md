# Непрерывный звук гонки

Двигатель, ветер, шины, атмосфера трассы и пит-лейна воспроизводятся через
Web Audio. Файл декодируется один раз и играет из PCM-буфера с нативным loop.
JS не перезапускает его по таймеру/ended и не перематывает на каждом повторе.
Плавные изменения gain/playbackRate выполняет звуковой поток. Высота двигателя
следует скорости воспроизведения; прежнее сохранение высоты HTML media при
изменении темпа не применяется.

## Стыки и переходы

При загрузке удаляется тихая краевая подкладка, конец совмещается с началом
коротким перекрытием до 60 мс. Ограниченный подбор фазы избегает противофазного
провала у тональных записей; поправка весов учитывает корреляцию и энергию.
Граница итогового буфера проходит между соседними исходными samples.
Если запись уже имеет естественный стык и ровные края, её период сохраняется.
Исходный файл на диске не изменяется. Авторские паузы внутри записи остаются.

Перерисовка Canvas/HTML не останавливает звуковой граф. Громкость меняется без
повторного декодирования и сброса фазы. При замене пути старый звук продолжает
играть до загрузки нового, после чего плавно сменяется им. Ошибка нового файла
сохраняет старую дорожку и даёт одно предупреждение, а не повтор каждый кадр.

Двигатель тихо работает до стартового сигнала, стихает при разрушении/финише,
меняет тон на скорости и во время обслуживания. Скользящие шины слышны только
при движении. Шум скорости, атмосфера трассы и пит-лейна плавно смешиваются.
Мягкая компрессия общего непрерывного микса уменьшает перегрузку на пиках.
При скрытии страницы микс приглушается с сохранением фазы; при закрытии гонки
загрузки отменяются, источники затихают и собственный AudioContext закрывается.
Звуковые контексты Foundry модуль не останавливает и не закрывает.

Однократные сигналы/столкновения остаются HTML Audio без циклической обработки:
для них пауза после окончания записи естественна. До 12 активных эффектов
защищают от накопления очень длинных пользовательских файлов. При mute,
скрытии и остановке они прекращаются. Автозапуск повторяется после действий
пользователя, а не при поступлении каждого сетевого кадра.

## Пользовательские записи

Подходят короткие непрерывные mono/stereo OGG, WAV и MP3, поддерживаемые браузером.
Пути настроек и уровни громкости сохранены. Лучше использовать несколько секунд
ровной работы механизма/шума, без слов, длинного вступления и финального затухания.
Сглаживание границы не превращает произвольную музыку или сигнал с внутренними
паузами в идеально ровный двигатель.

Для непрерывных дорожек действуют ограничения: файл до 16 MiB, до 120 с и
32 MiB декодированного PCM на запись, кэш до 64 MiB. Это ограничения хранения
подготовленных буферов; во время декодирования возможны временные копии.
Путь загружается один раз для нескольких ролей, неиспользуемые записи вытесняются
при заполнении кэша. Удалённый сервер должен разрешать загрузку через CORS;
обычные локальные пути FilePicker работают с того же сервера Foundry.

В диагностическом отчёте гонки есть backend, состояние контекста, число циклов,
источников, объём кэша и число зарегистрированных ошибок. Политика браузера
может требовать клик/нажатие клавиши для первого звука.

## Проверка 2 ноября 2026

Исходная версия — `54f8d9b`. Проверен указанный пользователем `engine2.ogg`:
Vorbis, stereo 44,1 kHz, 2,139 с. В самом файле длинной тишины на краях нет.
В 14-секундной пробе реального Chromium с AudioWorklet старый HTML-проигрыватель
на 0,68× и 1,58× давал окна по 10–20 мс с RMS до 21%/15% обычного уровня.
Новый BufferedLoops на том же стенде имел минимумы 87%/91% и ни одного окна
ниже половины медианы. Это измерение RMS, не оценка воспринимаемой громкости.
Короткое блокирование основного потока 150 мс входило в пробу. Точный вклад
стыка, изменения темпа HTML media и блокирования по отдельности не измерялся.

Штатные OGG не дали длинной абсолютной тишины в старом проигрывателе, поэтому
утверждать универсальную паузу его декодера нельзя. У них измерены скачки
на границах; кроме того, старый код доказуемо сбрасывал фазу при перемонтировании
окна и изменении любой звуковой настройки. У MP3 с добавленной краевой тишиной
старый проигрыватель давал 400 мс провала, новый — ни одного почти беззвучного окна.

OfflineAudioContext проверил 80 комбинаций: пять штатных OGG, пользовательский
engine2, MP3/WAV с подкладкой тишины; 44,1/48 kHz; скорости 0,5/0,68/1/1,58/2,2.
На двух стыках каждого рендера не было 5-мс окна ниже 10% опорного RMS.
Подготовка этих коротких записей заняла 0,7–12,2 мс один раз на загрузку на данном
стенде (максимум — первый штатный двигатель; пользовательский engine2 — 0,7 мс).
Максимальный sample проверенного пятислойного микса — около 0,94, без цифрового
клиппинга. Это выборка и один стенд, а не гарантия для любого файла/устройства.

Node-регрессии проверяют stereo, тишину, готовые периодические записи,
тональное взаимогашение, плавные параметры, накопление малых изменений,
повторную загрузку/перерисовку, смену файлов, отмену устаревших загрузок,
autoplay, mute, скрытие и освобождение ресурсов. Новый прогон в полном мире
Foundry 13.351 + Forbidden Lands 13.0.5 ещё требуется перед выпуском.

Базовое поведение API сверено по первичным источникам:
[AudioBufferSourceNode.loop](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode/loop),
[decodeAudioData](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/decodeAudioData),
[AudioParam.setTargetAtTime](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime).
